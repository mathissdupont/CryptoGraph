# Expanded Python key-origin development checkpoint

This follows the [original eight-case checkpoint](DEVELOPMENT-2026-10-27.md).
All 24 programs and all source-inspection proposals are development material.
No independent reviewer or approved reference label is recorded. Development
work continues with an explicit provisional mode; approval fields remain empty.

## Experiment completed

The corpus now spans PyCryptodome AES, pyca AES/AESGCM, imported constructor and
RNG aliases, configuration/default sources, mixed and partial sets, wrappers with
actual arguments and early returns, opaque factories, loops and dynamic keywords.
These are small designed examples, not a representative real-project sample.

The bounded policy ran in three conditions in the same Python/JEP Docker image,
with the current checkout mounted read only and networking disabled:

| Condition | Declared sites | Complete | Partial | Abstained | CALLS used |
| --- | ---: | ---: | ---: | ---: | ---: |
| Source only | 24 | 13 | 1 | 10 | 0 |
| AST CALLS | 24 | 17 | 1 | 6 | 4 |
| Fraunhofer CALLS | 24 | 15 | 1 | 8 | 2 |

Each condition produced one source-matched claim per declared site, with no
structural audit errors. Input hashes and candidate spans matched across cells.
The legacy matcher found 23 declared targets and missed `constructor_alias`.
That missing detection is reported separately from abstention. Its coarse
strings are not transformed into a fabricated set/modality accuracy score.

Source-only analysis withholds graph witnesses from the same interpreter.
Adding admissible AST CALLS made four wrapper source sets available. CPG CALLS
supported two; `misleading_helper` and `wrapper_actual_parameter` lacked a
matching admissible witness. This is a local observation about exported graphs
and this gate. It does not prove AST superiority, CPG ineffectiveness or a DFG
result. Neither graph condition currently performs DFG value recovery.

No resolved source set disagreed with the provisional proposals. Agreement with
assistant source-inspection proposals is not independent accuracy. The proposals
were written before running the added examples, but development exposure and
shared author/model assumptions remain. Partial-source semantic scoring is not
implemented. One boundary disagreement remains on `unsupported_loop`:
`local_assignment` was proposed, while the analyzer emits `expression` after an
unsupported write. This is retained as an issue to investigate, not relabeled to
improve agreement.

## Executable external-tool feasibility check

[PQCensus](https://github.com/XiantingWu/PQCensus) was inspected and run from the
unmodified Apache-2.0 source revision
[`535d56f15fa9fa83ce3ea46faf0c2ad19291fcd8`](https://github.com/XiantingWu/PQCensus/tree/535d56f15fa9fa83ce3ea46faf0c2ad19291fcd8).
The adapter uses its public `audit` API in a separate interpreter, preserves its
native JSON and matches exact zero-based Python source spans. It does not install
the tool, alter its rules or execute target source. No LLM/API calls were made.

A separate positive control produced SHA-256 and RSA findings at both expected
call sites. All 24 corpus files were processed with no parser errors or reported
scan-limit skips, but the native audit contained no findings for these AES
examples. Source inspection found no AES-constructor branch in this revision's
Python classifier. Its finding contract exposes purpose/evidence, rather than
our ultimate key-source set/completeness/modality contract. The overlap is
therefore insufficient for a key-origin accuracy comparison. Zero findings are
not counted as 24 abstentions or as invented origins. The designed target list
does not annotate every other crypto site, so it also cannot establish general
detection precision.

To reproduce, clone the external source into an ignored local directory and pin
the inspected revision, then run:

```bash
python scripts/observe-pqcensus.py --checkout output/pqcensus-535d56f --out-dir output/pqcensus-observation
```

The checkout must be clean at the exact revision. The adapter retains commit,
license/source/adapter hashes, positive-control output, parser errors, limits,
native results and per-site matching. External code is not vendored into this
repository. This is a feasibility observation, not replication of that tool's
published/author-reported benchmarks.

## Reproduction and interpretation

Local verification passed 101 tests, including the real Java exporter and UI
checks. The default scorer returned exit 2 with no reviewed score for the actual
pending packet. The three-cell Docker run completed after the final harness
changes, with matching code/candidate/provisional-reference snapshots.
The committed [development record](../../research/python-key-origin/development-observations.json)
retains counts, per-case outputs, environment/image identity and raw-artifact
fingerprints. The local run records the pre-commit revision with a dirty working
tree; input hashes identify the actual analyzed source. Code hashes compare cells
within a run and need not match raw line endings in a different checkout.

The [corpus README](../../research/python-key-origin/README.md) provides the
single-command Docker matrix. The matrix rejects stale output directories,
checks candidate/source/config/code snapshots, records all three conditions and
optionally compares matching provisional proposals. Provisional scoring refuses
held-out splits and never changes independent-review records. Default scoring
still refuses a pending review template. CI retains matrix outputs as artifacts.

The next evidence required for a paper is a pinned real-project sample with reuse
terms, annotation/review and recorded disagreements, shared-API comparators,
partial-claim semantics and a controlled DFG experiment. Reviewer availability
does not prevent corpus acquisition, tool reproduction or implementation work.
These 24 examples alone do not establish a publishable general contribution.
